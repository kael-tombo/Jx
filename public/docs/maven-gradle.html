Maven and Gradle

How jx plans to work with existing Maven and Gradle projects: export, import, compatibility and delegate modes.

Everything on this page is planned. No mode runs today.

Position

jx does not replace Maven or Gradle. It reuses Maven Central and keeps the existing build tools reachable. The design has four levels of contact with them.

The destination is everyday work through commands such as jx run. Maven and Gradle stay available when a project needs them.

The four modes

The four planned interop levels. All are planned for V1.
Mode What it would do Status
Export Write a Maven or Gradle build from the jx manifest. Planned for V1
Import Read an existing Maven or Gradle project into a jx manifest. Planned for V1
Compatibility mode Use the existing build files while jx supplies the toolchain and commands. Planned for V1
Delegate mode Call Maven or Gradle for the build. Planned for V1

Import is the entrance. Export is the exit.

Gradle coverage

Gradle support covers a declarative subset of the build model. Projects outside that subset would use delegate mode, where Gradle performs the build and jx supplies the commands around it.

The subset is not final. It will be documented when it is settled, with the cases it cannot express named in public.

Maven plugins

Maven plugins are not run natively in V1. Delegate mode calls Maven or Gradle, so an existing plugin setup can still run. A plugin host is planned for later.

The exit

Export is the promise that a project can leave. A jx project can become a Maven or Gradle project with a build file those tools understand. A one-way conversion would be lock-in, and lock-in is a non-goal.

See the planned commands for import and export, or the concepts behind the manifest.
