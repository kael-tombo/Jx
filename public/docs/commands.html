Command reference

The planned jx commands for V1 and their intended behaviour. Draft; not released.

Every command in this table is part of the V1 plan. None is released. Flags, output formats and exit codes are not fixed.

The full V1 command set. Every row is proposed.
Command What it would do Status
jx new Scaffold a project with a manifest and a main class. Planned for V1
jx init Add a manifest to an existing source tree. Planned for V1
jx add Add a dependency and resolve it. Planned for V1
jx remove Remove a dependency and update the lockfile. Planned for V1
jx lock Resolve dependencies and write exact versions. Planned for V1
jx fetch Download and verify the artifacts the lockfile pins. Planned for V1
jx tree Print the resolved dependency graph. Planned for V1
jx why Explain why an artifact is in the graph. Planned for V1
jx build Compile main sources and resources. Planned for V1
jx run Build, then start the main class. Planned for V1
jx test Compile test sources and run JUnit. Planned for V1
jx clean Remove build output. Planned for V1
jx jdk List and install the JDKs jx manages. Planned for V1
jx import Read a Maven or Gradle project into a manifest. Planned for V1
jx export maven Write a Maven build from the manifest. Planned for V1
jx export gradle Write a Gradle build from the manifest. Planned for V1
jx doctor Check home, cache, network, system Java and disk. Planned for V1

Command shape

The design target is one small command set that covers the common path. The three commands used by the quickstart would be jx new, jx run and jx test.

Import and export are the boundary with existing builds. Maven and Gradle explains the four planned modes. Concepts explains the manifest and lockfile the commands maintain.

Not fixed

Subcommands, flags, machine-readable output and exit codes are open questions. They will be documented only when a release exists to describe.
