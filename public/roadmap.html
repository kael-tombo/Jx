Roadmap.

Milestones M0 to M8, the gates between them, and the honest status of V1. The source tree is complete; the release is pending a tag.

M0–M8 are implemented in the source tree. No tagged public release exists. The gates below remain open where they have not been independently verified.

Milestones

  1. M0Implemented

    Foundations

    Workspace, continuous integration, decision records, configuration and diagnostics. The base every later milestone sits on.

  2. M1Implemented

    Toolchain and hello

    JDK download and pin, project scaffolding, and a first build and run with no Java installed.

  3. M2Implemented

    Repository and POM model

    Maven Central client, cache, checksums, a POM model and dependency version ordering.

  4. M3Implemented

    Resolver

    Dependency graph, conflict policy, a reproducible lockfile, and the tree and why commands.

  5. M4Implemented

    Build and test

    javac integration, fingerprints that skip unchanged work, resources, and a JUnit launcher.

  6. M5Implemented

    Run and package

    Main discovery, a run command, distributions and a jar. Export to Maven.

  7. M6Implemented

    Runtime trimming

    jdeps and jlink, with a fallback when a project cannot be trimmed. This is optional packaging for deployment; it does not change what the JDK ships.

  8. M7Implemented

    Maven and Gradle interop

    Import, compatibility mode, delegate mode, and exports in both directions.

  9. M8Implemented

    Release hardening

    Documentation, an install path, a security review and a launch checklist.

Post-V1 adapters

The adapter line has started without changing the V1 boundary. These are implemented in the source tree and covered by its tests; no tagged release exists yet.

  • JBang scripts. jx script hands a Java, JShell, Kotlin, Groovy or markdown script to JBang, forwards arguments and --offline, exports a pinned JDK when the script is inside a jx project, and returns JBang's exit code.
  • jot import. jx import reads a Java-only, single-module jot.toml, including libs.versions.toml catalogs and [processors]. Workspaces, path dependencies, Kotlin toolchains and non-Temurin pins are refused with a next step.
  • OS packages. The release workflow renders Chocolatey, Homebrew, Scoop and winget manifests from SHA256SUMS and attaches a Chocolatey .nupkg. Submission to those repositories remains a maintainer action.

Framework adapters, Kotlin and Scala compilation, and a Maven plugin host remain unscheduled.

Decision gates

Implementation and verification are separate. These gates remain open or unverified; a tagged release does not close them by itself.

  • Gate Open

    Resolver parity with Maven

    A representative set of POMs resolves to the same versions Maven selects. The repository tests pass; an independent Maven parity run is not published.

  • Gate Open

    Happy-path coverage

    A new user completes the hello flow on a machine with no Java installed, following only the published quickstart. The flow has been exercised in the source tree, not by an independent new user.

  • Gate Open

    User preference

    People choose jx for a new project after trying it beside their current workflow. No such trial has run.

How to read this page

Implemented means the source tree contains the work and its tests. It does not mean a gate has passed or that a release exists. The gates record what still needs independent evidence; the page will change when they do.

The landing page carries a short version of this timeline. The vision explains the tests behind the gates.
