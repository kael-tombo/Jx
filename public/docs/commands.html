Command reference

The jx commands in V1 and their behaviour. V1 is implemented; release binaries are pending.

Every command in this table is implemented in the V1 source tree. Flags, output formats and exit codes can still change before the v1.0.0 tag.

The full V1 command set, implemented in the source tree.
Command What it does Status
jx new Scaffold a project with a manifest and a main class. Implemented
jx init Add a manifest to an existing source tree. Implemented
jx add Add a dependency and resolve it. Implemented
jx remove Remove a dependency and update the lockfile. Implemented
jx lock Resolve dependencies and write exact versions. Implemented
jx fetch Download and verify the artifacts the lockfile pins. Implemented
jx tree Print the resolved dependency graph. Implemented
jx why Explain why an artifact is in the graph. Implemented
jx build Compile main sources and resources. Implemented
jx run Build, then start the main class. Implemented
jx test Compile test sources and run JUnit. Implemented
jx package Write a thin jar, a dist tree and, with --fat, a merged jar. Implemented
jx image Build a runtime image with jdeps and jlink; --full keeps every linkable module. Implemented
jx clean Remove build output. Implemented
jx jdk List and install the JDKs jx manages. Implemented
jx import Read a Maven or Gradle project into a manifest. Implemented
jx export maven Write a Maven build from the manifest. Implemented
jx export gradle Write a Gradle build from the manifest. Implemented
jx doctor Check home, cache, network, system Java and disk. Implemented

Command shape

One small command set covers the common path. The three commands used by the quickstart are jx new, jx run and jx test.

Import and export are the boundary with existing builds. Maven and Gradle explains the three interop levels. Concepts explains the manifest and lockfile the commands maintain.

Before the tag

The command set is fixed for V1. Flags, machine-readable output and exit codes can still change before v1.0.0 is tagged.

jx
