Accessibility.

How this site aims to meet WCAG 2.2 AA, what has been checked, and what remains limited.

Target

This site aims at WCAG 2.2 level AA. The aim covers the whole site: the landing page, the vision and roadmap, the documentation, and the plain pages.

What is built in

  • Semantic HTML with landmarks, one main heading per page and a logical heading order.
  • A skip link, visible focus styles and full keyboard use.
  • Text alternatives for the architecture diagram and the terminal transcript.
  • Status is written in words, never carried by colour alone.
  • Light and dark themes that follow the system preference, with a manual toggle.
  • Motion is limited. The terminal typing effect is off when reduced motion is requested, and it has pause and show-all controls.
  • Pages remain readable and navigable with JavaScript off.
  • Layouts work at narrow widths and at zoom.

What has been checked

These checks ran against the built pages:

  • axe with the WCAG 2.0, 2.1 and 2.2 A and AA rule sets found no serious or critical issue on any page, in light or dark.
  • Lighthouse reported no accessibility failure on the pages tested.
  • Every text colour pair meets the AA contrast minimum, and control borders meet the UI minimum, in both themes.
  • The browser tests cover the skip link, keyboard focus, the theme toggle, native FAQ controls, the copy announcement, reading with JavaScript off, and reflow at a narrow width.

An independent audit by a disabled user has not happened yet. Until it does, this page does not claim one.

Known limitations

  • Wide tables scroll horizontally on small screens. The scroll region can be reached and scrolled with a keyboard.
  • The terminal typing effect is decorative. The full transcript is always present for assistive technology.
  • Some values on this site are placeholders. They are marked as such and are not presented as final content.
