Glossary

Terms used in the jx documentation, in plain language.

Definitions describe V1 behaviour. Terms marked after V1 are not implemented yet.

Adapter
A post-V1 component that connects jx run to a framework such as Spring Boot, Quarkus, Vert.x or Jakarta EE.
ADR
Architecture decision record. A short, dated note that records a choice and its consequences.
Compatibility mode
The mode where jx keeps an existing Maven or Gradle build and delegates build, test and clean to it, while supplying the pinned JDK and command surface.
Conflict policy
The rule used when two dependencies ask for different versions: highest compatible version within a major; a hard error across majors.
Delegate mode
Another name for compatibility mode: jx calls Maven or Gradle rather than running its own pipeline.
Design preview
This website. It describes V1 and is not a release archive.
JDK
Java Development Kit. The compiler and runtime tools a Java project needs.
Lockfile
A file written by the resolver that records exact artifacts and checksums for a reproducible build.
Manifest
The single project file, project.toml, which records the project name, JDK pin, dependencies and entry point.
Maven Central
The public repository where Java libraries are published. jx reuses it and does not replace it.
Maven standard layout
The directory convention with main sources under src/main/java and tests under src/test/java.
Milestone
A named stage of the V1 build, M0 to M8. The implementation is complete; the roadmap keeps the decision gates visible.
Platform tool
A single command-line tool that owns an ecosystem's everyday workflow: one manifest, one command set, dependency resolution and builds. Cargo, uv and npm are examples. jx is an independent implementation for Java, not an official platform tool.
POM
Maven's project object model. jx reads POM metadata to resolve dependencies.
Resolver
The component that reads dependency metadata, selects versions and writes the lockfile.
Runtime image
A Java runtime assembled for deployment, optionally trimmed with the JDK's jlink when packaging. It is a deployment artifact, not a platform tool, and jx does not claim it fixes the JRE's size.
Status
A word on this site that says how settled a claim is: idea, draft, proposed, accepted, implemented or shipped. Implemented means the 1.0.0 source tree contains the behaviour and tests; shipped means a tagged release contains it. No page uses shipped yet.
Toolchain
The JDK installation jx manages and pins for a project.
V1
The first public version, 1.0.0. Its scope is Java only, with the Maven standard layout. The source tree is complete; a tag is pending.
Vision
The long-form statement of why jx exists, what smooth means, and what the project will not match.
