Glossary

Terms used in the jx design documents, in plain language.

Definitions describe the proposed design. They do not claim that any term is implemented.

Adapter
A planned component that connects jx run to a framework such as Spring Boot, Quarkus, Vert.x or Jakarta EE. Adapters are after V1.
ADR
Architecture decision record. A short, dated note that records a choice and its consequences.
Compatibility mode
A planned mode where jx uses an existing Maven or Gradle build while supplying its own toolchain and commands.
Conflict policy
The rule used when two dependencies ask for different versions. Proposed: highest compatible version within a major; a hard error across majors.
Delegate mode
A planned mode where jx calls Maven or Gradle to perform a build.
Design preview
This website. It describes a proposal and is not a release of the tool.
JDK
Java Development Kit. The compiler and runtime tools a Java project needs.
Lockfile
A file written by the resolver that records exact artifacts and checksums for a reproducible build.
Manifest
The single project file, project.toml, which records the project name, JDK pin, dependencies and entry point.
Maven Central
The public repository where Java libraries are published. jx plans to reuse it, not replace it.
Maven standard layout
The directory convention with main sources under src/main/java and tests under src/test/java.
Milestone
A named stage of the plan, M0 to M8, with a decision gate before it closes.
Platform tool
A single command-line tool that owns an ecosystem's everyday workflow: one manifest, one command set, dependency resolution and builds. Cargo, uv and npm are examples. jx is an independent proposal for Java, not an official platform tool.
POM
Maven's project object model. jx would read POM metadata to resolve dependencies.
Resolver
The component that reads dependency metadata, selects versions and writes the lockfile.
Runtime image
A Java runtime assembled for deployment, optionally trimmed with the JDK's jlink when packaging. It is a deployment artifact, not a platform tool, and jx does not claim it fixes the JRE's size.
Status
A word on this site that says how settled a claim is: idea, draft, proposed, accepted, implemented or shipped. The last two are not used until a release exists.
Toolchain
The JDK installation jx manages and pins for a project.
V1
The first planned release. Its scope is Java only, with the Maven standard layout.
Vision
The long-form statement of why jx exists, what smooth means, and what the project will not match.
